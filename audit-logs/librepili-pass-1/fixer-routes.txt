## 1. What changed, per item

**R1 — deleting a download vs. the exported folder**
- New `showDeleteDownloadDialog` (`lib/pages/download/delete_dialog.dart`) shows a checkbox "同时删除导出的视频文件", **unchecked by default**. It returns null when cancelled, otherwise whether to delete the export.
- `deleteDownload` and `deletePage` take `deleteExported` (default false). The exported folder is deleted only when it is true.
- Every delete entry point uses the new dialog:
  - long-press on an item (`DetailItem`, used by the downloads, detail, downloading and search pages)
  - long-press on a multi-part page
  - multi-select on the downloads, detail and search pages
- The downloading queue has no exported file yet, so its dialog shows no checkbox. Its multi-select still uses the old confirm dialog.

**R2 — self-test isolation**
- `isSelfTestProfile` is set from `--selftest` before any storage init.
- App data (Hive boxes, WebView data) then lives in `<appSupport>/selftest`. Downloads use the default download folder inside it; the user's custom download path and Android external storage are ignored.
- The Android public `Download/LibrePili` export is skipped too.
- The self-test's clean-up deletes, which now pass `deleteExported: true`, can therefore only touch the isolated folders.
- The report now records `dataDir` and `downloadDir`.

**R3 — old single-URL (Type1) downloads**
- Every `durl` segment is now downloaded, not just the first. Each segment has its backup URLs, the segments run one after another as `0.mp4`, `1.mp4`, …, and progress is shown over their total size.
- New pure-Dart FLV demuxer `lib/utils/flv_demux.dart`, a `part` of `mp4_remux.dart`, so it reuses the existing mp4 writer:
  - H.264 video and AAC audio.
  - It reads `avcC` and the AudioSpecificConfig from the sequence-header tags, and parses the SPS for the picture size, including cropping.
  - It keeps composition time offsets and keyframe flags.
  - Segments whose timestamps restart are placed after the previous one.
  - If audio and video start at different times, an empty edit keeps them in sync.
  - Sample bytes are copied unchanged (a chunk can now come from its own segment file).
- Merge rules:
  - FLV → remux to a real mp4.
  - Unsupported codec → the original data is kept under its real extension (`<base>.flv`, or `<base>.2.flv` and so on for more segments), and the Android media scan is told `video/x-flv`.
  - A single mp4 segment is moved as before.

**R4 — offline comments and images**
- Comment pictures and the emotes used in comment text are downloaded with the comments into `comments_images/`, one file per URL hash.
- The comments JSON records `pictures` and `emotes` as paths relative to the comments file. This follows the existing comment-count settings; there is no separate toggle.
- `LocalReplyPanel` shows a local placeholder instead of the avatar, draws emotes inline and pictures as thumbnails (tap to enlarge), all from local files. The panel no longer makes any network request.

**R5 — hide-interaction scope**
New shared gate `LoginPolicy.canInteract`: logged in and the switch off. Comments and danmaku still display everywhere; only writing UI is hidden. Entry points gated this pass:
1. Dynamic, article/opus, music and match detail: the "评论" floating button (`common_dyn_page.dart` `replyButton`).
2. Comment page (`MainReplyPage`, also used by audio): the floating button.
3. PGC reviews: the "写短评 / 写长评" button.
4. Live room input bar: the "发送弹幕" tap and the emoji button. The danmaku toggle and like button stay.
5. Live room player bar "发弹幕" (it was login-only before).
6. Live chat long-press "@TA".
7. `LiveRoomController.onSendDanmaku` returns early (covers any other path).
8. `VideoDetailController.showShootDanmakuSheet` returns early (covers the player's keyboard shortcut).
9. `ReplyController.onReply` and `VideoReplyReplyController.onReply` return early, as a backstop for every comment and reply opener.

Already gated before this pass, and checked: the video-page comment button, the reply button on each comment item, and the video page's "发弹幕" in portrait and fullscreen. A search for the three write APIs (`replyAdd`, `shootDanmaku`, `sendLiveMsg`) found only the three writer pages, and every path into them is now gated. ## 3. Uncertainty list

- **R1**
  - If an entry is deleted *while it is merging*, its just-written output is still always removed (iter-1 behaviour), because the user never saw an export to keep.
  - The downloading queue's multi-select keeps the plain confirm dialog; nothing there has an export.
- **R2**
  - The isolated profile has no accounts or settings, so the self-test always runs anonymous with default settings. Any scenario that relied on the real profile (a login or custom settings) will behave differently.
  - The image cache in the shared temp folder is not isolated. It is a cache, not user data.
- **R3**
  - **Not tested on a real FLV from Bilibili.** Only synthetic FLVs were tested.
  - Resuming a finished segment relies on the server answering the `Range` request with a 416 that carries `Content-Range: bytes */N`. Without that header, the segment is downloaded again (slower but correct).
  - Multi-segment mp4 (not FLV) is kept as separate `.mp4` parts. The remuxer can't join progressive mp4 files.
  - A codec configuration that changes mid-stream is treated as unsupported, so the FLV is kept as is.
  - An in-app player fallback (merge failed) still plays only segment 0, as before.
- **R4**
  - Images come over the network at download time through `Request.dio`, not bound to any account.
  - A picture that fails to download is simply left out.
  - Images are downloaded one by one, so a download with many images makes comment export slower; it no longer blocks the queue (iter 1).
- **R5**
  - I searched for the three write APIs and all their callers. Writing features outside comments, danmaku and live chat are not gated: private messages, reposting a dynamic with text, creating dynamics.
  - The live-room gate uses `LoginPolicy.canInteract`, i.e. `Accounts.main.isLogin`, while the input bar itself still checks `LiveRoomController.isLogin` first.
- **R6**
  - Changing the Linux application id and the macOS/iOS bundle id moves those platforms' data folders. Anyone who already ran a LibrePili build on those platforms under the old ids starts with an empty profile.
  - The Android Java/Kotlin package (`com.example.piliplus`) and the audio notification channel id were left alone. This matches Android's current setup, where only `applicationId` changed.
  - Settings export and WebDAV file names (`piliplus_*`) are unchanged.
