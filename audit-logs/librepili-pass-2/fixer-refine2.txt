The Linux desktop entry now accepts files: `Exec=librepili %U` instead of `%u`. It also advertises nine video MIME types, one for each extension in `LocalPlayer.videoExtensions`: mp4, mkv, webm, mov, m4v, flv, avi, ts and wmv. The `bilibili` scheme handler is unchanged. This is not tested on Linux.

I checked everything that installs or references the file, and none of it needed changing:
- **deb:** `linux_x64.yml:63` copies the file as is, and `DEBIAN/postinst` / `postrm` already run `update-desktop-database`, so the new MIME types get registered.
- **rpm:** lines 105 and 138 install the file unchanged, and the `%post` / `%postun` steps (144, 148) also run `update-desktop-database`.
- **AppImage:** lines 190–191 copy the file. The two `sed` lines at 207–208 replace text with itself, so they have no effect on `%U`.

One behaviour to know about: file managers usually pass a `file://` URI rather than a plain path. `main()` doesn't recognise a URI at launch, so the file is opened by the link-stream handler I added last round, which converts `file:` URIs to paths. It still opens once either way. With several files selected, only the first is opened.
