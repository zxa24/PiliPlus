### Finding 1: Linux purge deletes every user's app data; uninstall kills all matching processes
(reported by independent auditors; duplicates merged - satisfy all of them)

- [P1] Linux purge deletes every user’s app data — assets/linux/DEBIAN/postrm:20-23  
  On `dpkg --purge`, this root maintainer script recursively removes `/home/*/.local/share/com.zxa24.librepili` and root’s app data. That can erase settings, local follows/favorites, logs, and other user-owned state for every account on the machine without per-user consent. Debian packages should generally remove package-owned files only; leave user data in place or provide an explicit in-app/user-scoped cleanup path.

- [P3] Uninstall kills all matching app processes system-wide — assets/linux/DEBIAN/prerm:3-6  
  `pkill -x librepili` during package removal terminates every process with that executable name, including sessions owned by other users. That can interrupt playback, downloads, or pending writes. Prefer not killing user processes from the maintainer script, or scope shutdown to a known package-managed service/session.

# Self-review before self-test (mandatory)

After applying ALL finding fixes but **before** running tests, do one
quick self-review pass. For each finding ask yourself two questions:

1. **Does my fix cover every case the finding's title and description

   `[PARTIAL]` on re-review and forces another round trip. Re-read the

before testing — do not return to the orchestrator with a known-partial

## Auto-repair test infrastructure (no-ask)

If running the detected test command fails because **the test infra
itself is broken** (not because the audit broke a behaviour), repair
the infra automatically and re-run. Do NOT ask. Surface the repairs
done in the `INFRA REPAIRS` line of the final report block.

INFRA-level patterns (auto-repair without asking):

- **Missing dependencies**: `npm install --ignore-scripts` /
  `pip install --only-binary=:all: -r requirements.txt` /
  `cargo fetch` / Playwright browser binaries (`npx playwright install`)
  missing → run the install. If install itself fails, surface that.
  These flags block the script-execution path that
  `dangerously-skip-permissions` + Bash would otherwise expose: npm's
  `--ignore-scripts` skips lifecycle hooks; pip's `--only-binary=:all:`
  refuses to build from source distributions, eliminating the
  `setup.py` execution path; cargo `fetch` doesn't run scripts;
  `npx playwright install` is a single-binary download. If a project's
  test deps require source builds (e.g. compiled extensions without
  prebuilt wheels) or a project genuinely needs lifecycle scripts to
  test, the install will fail — surface that to the user as a
  route-choice rather than silently relaxing the constraint.
- **Broken paths in test scripts**: hardcoded paths to legacy
  directories (e.g. `tests/translator_app/app.js` when `app.js`
  moved to root) → fix the path references in the test scripts.
- **Stale test config**: `playwright.config.js`, `pytest.ini`,
  `package.json scripts.lint` pointing at non-existent files →
  update the config.
- **Missing test helper imports**: helpers moved/renamed since tests
  were written → align imports.
- **Test selectors too loose for new UI**: Playwright spec uses
  `label.btn.primary` and a recent commit added a 2nd matching
  element → tighten the selector (`:has-text(...)` or `#id`).
- **Permission issues on test artifact dirs**: tests can't write to
  `tests/screenshots/` etc. → `mkdir -p` and re-run.

REAL behavioural failures (do NOT auto-repair, just report):

- Assertion failures: `expect(x).toBe(y)` failed with x !== y
- Behaviour deltas: feature flag now off, UI element absent, output
  format different from expected
- Anything where the test code itself is correct and ran successfully,
  but the assertion conclusion was negative

Auto-repair loop limit: up to 3 cycles per test runner. If a runner's
tests still fail with INFRA errors after 3 repair attempts, stop
repairing it and report the remaining failures as `INFRA-PERSISTENT`.
